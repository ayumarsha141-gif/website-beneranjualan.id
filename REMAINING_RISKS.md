# Remaining risks and launch gates

- Six seeded demo products remain in the database but are archived (`is_active=0`) and excluded from public catalog/cart/checkout. Their example prices/stocks are not valid offers; do not reactivate them as live products. Import/verify owner product names, prices, stocks and photo mappings.
- Store contact, bank, address, shipping, operating hours and final legally reviewed policy are owner-supplied configuration. Do not accept live orders until these are complete and tested.
- Payment is manual transfer only by default. There is no payment gateway or automated payment reconciliation. Admin must verify receipts before marking paid.
- Shipping is not integrated with a carrier or route/distance pricing; the default workflow requires admin confirmation.
- Password reset does not send email or issue a functional reset token; the page should not be represented as a working self-service recovery feature.
- Wishlist, custom-bouquet ordering, product variations, pickup, carrier integration/automatic shipping quotes, and payment gateway are not implemented. They are intentionally not advertised because storage/workflows or verified business services are not configured; add them only with owner-approved requirements.
- Existing bundled catalog photos now have responsive 480px/960px WebP variants and the main storefront images emit `srcset`. Admin-uploaded images remain original JPEG/PNG/WebP files (no automatic variant generation yet); run a measured performance audit before launch.
- Homepage, catalogue, and all six 3D camera stops were visually checked in Edge/SwiftShader at desktop/mobile viewport sizes; screenshots are in `visual-evidence/v2-six-scenes/`. The procedural low-poly geometry is a true 3D prototype, but it is not bespoke GLB art and has no real-device FPS/GPU benchmark. Full route-by-route responsive/accessibility audit, upload-abuse checks, scheduled/offsite backup policy, and production HTTPS checks remain outstanding. A local dump/restore drill passed, but that does not validate hosting backups. PHP lint and local DB setup are not a production-readiness certification.
- Sequential full guest checkout over HTTP (including CSRF, server-calculated price, stock deduction, idempotent retry and cleanup) passed. Concurrent stock locking was exercised at the MySQL transaction level with two processes; simultaneous full HTTP checkout race testing remains outstanding. Apache `.htaccess` routing for `/robots.txt` also needs verification on the target host.
- Confirm deployment document root excludes `.env`, migrations, scripts, logs, and backups; enforce HTTPS, secure session cookies, least-privilege DB access, rate limiting/monitoring and offsite backups.
- The supplied legacy database fragments were not restored. Existing rows in the currently configured database were retained; those are not evidence that records from the old fragments were recovered.
